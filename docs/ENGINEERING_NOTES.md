# قرارات التنفيذ والهندسة - الوهيب ERP (نواة تشغيلية تجريبية)

**المرجع:** `Blueprint_v1.1_Merged.html` المرفق، تاريخ 25 أكتوبر 2026. هذا المصدر يسمي نفسه Draft/Proposed ويشترط اعتماد المالك والمحاسب والتوافق القانوني قبل إطلاق تجاري.

## المعمارية المقامة

```
Wahib.Desktop (Windows WPF)
         ↓
Wahib.Application (Contracts / DTOs)
         ↓
Wahib.Domain (Amounts, Accounting, Permissions)
         ↑
Wahib.Infrastructure (SQLite transactions, reporting, backup)
```

هندسيًا ما يزال Orchestrator وSQL في Infrastructure بدل فصل Use Cases كاملة في Application، وتعمل الواجهة بتصميم code-behind بدل MVVM كامل. **هذه انحرافات واضحة عن خطّة المشروع وليست تنفيذا حرفيا لها**.

## قواعد المحاسبة التي طُبقت في الكود

- تخزين الأموال والكميات في SQLite كأعداد INTEGER مقيسة بعامل 10,000 لكل منهما، مع حسابات وسيطة C# decimal؛ لا يتم تخزين الرصيد المالي بصيغة REAL.
- `Amount.Balanced` يرفض القيود غير المتوازنة وخطوط المدين/الدائن الثنائية.
- `PostDocument` يستخدم معاملة SQLite واحدة للدفتر والمخزون وتحديث حالة الفاتورة؛ إعادة الترحيل تعيد الحالة الحالية ولا تكرر القيود.
- حركات الصنف مصدر الحقيقة للكمية والقيمة، ويُمنع بيع ما يتجاوز المخزون. المتوسط المتحرك يحسب تكلفة الخروج، ويزيل الرصيد المالي كليًا عند إخراج آخر الكمية.
- مردودات المبيعات تستعمل سعر البيع والتكلفة التاريخية للسطر الأصلي، لا السعر الحالي. مردود المشتريات يخرج بتكلفة المخزون الحالية ويسجل الفرق في حساب فروق أسعار المشتريات.
- بيع نقدي يثبت قيد فاتورة البيع مع قيد تحصيل داخلي مربوط ضمن المعاملة نفسها، ولا يترك ذمة مفتوحة.
- فترات مغلقة تمنع اعتماد جديد؛ لا يُسمح بالتأريخ السابق لحركة مخزون لاحقة على الصنف.
- سداد فاتورة لا يتجاوز الرصيد المتبقي بعد التخصيصات والمرتجعات.
- يتم حفظ ملفات شركات منفصلة في `%LOCALAPPDATA%/AlWahibERP/companies`.

## سياسة الخصائص المؤجلة

هذه نواة تشغيلية **وليست إصدارًا تجاريًا**. لم تُنفّذ منظومة تعدد العملات وسعر الصرف، ملفات الضرائب المحلية، ترخيص رقمي Offline موقّع، الطابعة الحرارية 80mm، الوحدات البديلة كرتون/حبة، تخصيص UI شامل، صلاحيات دقيقة على مستوى الحقول، التشفير المحلي والـACL التثبيت، مسودات قيود قابلة للتحرير، migrations مترابطة EF Core، الفحص الأمني والتدقيق القانوني. لا تُستعمل لأرصدة حقيقية دون اختبارات Windows واعتماد محاسب.

## انحرافات تقنية مؤقتة

- يستخدم `Microsoft.Data.Sqlite` (ADO.NET) مباشرة بدل EF Core لضبط المعاملات وINTEGER SQL بوضوح، ولذلك *لا توجد* EF Core Migrations حتى الآن. تعتمد قاعدة البيانات Schema v1 ثابتة؛ لا تُجرى هجرة تلقائية عند تحديث المخطط.
- واجهات WPF code-behind وليس MVVM كاملًا. يساعد ذلك على فتح أول واجهة بملفات أقل، لكنه يحتاج إعادة تنظيم قبل توسعة المنتج.
- تستخدم PBKDF2-SHA256 مع 350,000 تكرار، وليس Argon2id، وفق بديل التوافق المذكور في المرجع.
- لا يُنفذ API لترخيص offline بمفتاح عام ولا ملف installer موقّع.
- طباعة PDF تتم عبر اختيار طابعة Microsoft Print to PDF من مربع حوار Windows، وليس بمحرك PDF مدمج.

## قراءة نموذج التهديد

التحكم داخل WPF وحده لا يمنع مالك الجهاز من قراءة/تغيير ملفات DB؛ سلسلة SHA256 للأحداث **تكشف** انقطاع السجل ولا تمنع حذف قاعدة البيانات كاملة. يجب توثيق Windows ACL ونسخ خارجي وتشفير مفتاحه وإجراء مراجعة أمنية قبل إطلاق.

## اختبار الترحيل

قبل نشر إصدار جديد من schema: النسخ باستخدام SQLite Online Backup، هجرة نسخة اختبار، فحص JournalEntry Balance، فرق Stock vs GL، rollback، ثم توقيع Release Gate. نسخة v1 لا تنفذ الهجرة نفسها.
